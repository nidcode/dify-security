# 12. DBパスワードの変更 (PostgreSQL)

Keycloak・LiteLLM・Dify が使う PostgreSQL のパスワードを変更する手順。

置き換え: `<GATEWAY_HOST>` `<GATEWAY_DOMAIN>` `<LITELLM_HOST>` `<LITELLM_PORT>` `<DIFY_HOST>` `<TEAM>` `<REPO_DIR>`。

## 最初に: `.env` を書き換えるだけでは変更できない

PostgreSQL のパスワードは **DBの中** に保存されている。`.env` の値が使われるのは、DBを
初めて作ったとき (データが空のとき) の一度だけで、以後 `.env` を変えても DB 側のパスワードは
変わらない。

そのため `.env` だけを書き換えてコンテナを作り直すと、アプリ側だけが新しいパスワードで接続しに
行き、次のエラーで **起動できなくなる** (データは消えない。`.env` を元の値に戻して作り直せば復旧する):

```
FATAL:  password authentication failed for user "<DBユーザー名>"
```

> `docker compose stop` → `start` (コンテナの停止・開始) では `.env` は読み直されないため、
> 旧パスワードのまま動き続ける (変更は反映されない)。
>
> `make gen-env-force` は `.env` のDBパスワードを作り直すため、実行すると同じ状態になる。
> 稼働中の環境では実行しないこと。

正しい順番は **① DB内のパスワードを変更 → ② `.env` を同じ値に書き換え → ③ コンテナを作り直す**。

| 対象 | VM | `.env` の場所と項目 | DBユーザー | 作り直しで止まるもの |
|---|---|---|---|---|
| A. Keycloak | Gateway VM | `<REPO_DIR>/.env` の `KEYCLOAK_DB_PASSWORD` | `keycloak` | Keycloak (全チームの新規ログイン) |
| B. LiteLLM | LiteLLM VM | `<REPO_DIR>/.env` の `LITELLM_DB_PASSWORD` | `litellm` | LiteLLM (全チームのLLM呼び出し) |
| C. Dify | Dify VM | `<REPO_DIR>/dify/instances/<TEAM>/.env` の `DB_PASSWORD` | `postgres` | そのインスタンスの Dify |

いずれも作り直しの間 (1〜2分程度) サービスが止まるため、利用の少ない時間帯に実施する。

### 新しいパスワードの決め方

英数字のみで作る (記号を含むと `.env` や接続URLの解釈で問題が起きることがある)。例:

```bash
openssl rand -hex 16
```

---

## A. Keycloak (Gateway VM)

### ① DB内のパスワードを変更

```bash
ssh <GATEWAY_HOST>
cd <REPO_DIR>
make gateway-psql
```

`keycloak=#` と表示されたら次を入力し、新しいパスワードを2回入力する (画面には表示されない):

```
\password keycloak
```

`\q` で終了する。

### ② `.env` を書き換え

`<REPO_DIR>/.env` の `KEYCLOAK_DB_PASSWORD=` の値を、①で入力したパスワードに書き換える。

### ③ 作り直して確認

```bash
make gateway-up
make gateway-ps   # keycloak・keycloak-db が healthy になるまで待つ
```

ブラウザで `https://<TEAM>.<GATEWAY_DOMAIN>/` を開き、ログインできればOK。

---

## B. LiteLLM (LiteLLM VM)

### ① DB内のパスワードを変更

```bash
ssh <LITELLM_HOST>
cd <REPO_DIR>
docker compose -p aiop-litellm --env-file .env -f compose.litellm.yaml \
  exec litellm-db psql -U litellm -d litellm
```

`litellm=#` と表示されたら次を入力し、新しいパスワードを2回入力する:

```
\password litellm
```

`\q` で終了する。

### ② `.env` を書き換え

`<REPO_DIR>/.env` の `LITELLM_DB_PASSWORD=` の値を、①で入力したパスワードに書き換える。

### ③ 作り直して確認

```bash
make up
make ps   # litellm・litellm-db が healthy になるまで待つ
curl http://<LITELLM_HOST>:<LITELLM_PORT>/health/liveliness
```

正常応答が返り、LiteLLM 管理画面にログインして **Virtual Keys** の一覧が表示されればOK。

---

## C. Dify (Dify VM・インスタンス `<TEAM>` ごと)

### ① DB内のパスワードを変更

```bash
ssh <DIFY_HOST>
cd <REPO_DIR>/dify/instances/<TEAM>
docker compose exec db_postgres psql -U postgres -d dify
```

`dify=#` と表示されたら次を入力し、新しいパスワードを2回入力する:

```
\password postgres
```

`\q` で終了する。

### ② `.env` を書き換え

`<REPO_DIR>/dify/instances/<TEAM>/.env` の `DB_PASSWORD=` の値を、①で入力したパスワードに書き換える。

### ③ 作り直して確認

```bash
docker compose up -d
docker compose ps   # 全サービスが running/healthy か確認
```

`https://<TEAM>.<GATEWAY_DOMAIN>/` にログインし、アプリ一覧が表示されればOK。

---

## 変更後に必ずバックアップを取り直す

「バックアップとリストア」の手順書で、変更したVMのバックアップ (DB・ファイル一式) を取り直す。

変更前のバックアップのファイル一式には **旧パスワードの `.env`** が入っている。同一VM上の
リストアでそれを展開すると、DB内 (新パスワード) と `.env` (旧パスワード) が食い違い、
上記のエラーで起動できなくなる。変更前のバックアップからリストアした場合は、展開後に
`.env` の該当項目を新しいパスワードに書き戻してから起動すること。

## うまくいかない場合

| 症状 | 対処 |
|---|---|
| ③で `password authentication failed` が出て起動しない | ①と②の値が一致していない。①をやり直して `.env` と同じ値を設定し、③を再実行する |
| ①で `\password` の後に何も起きない | パスワード入力待ち。画面に表示されないまま入力して Enter (2回) |
| 元に戻したい | ①で旧パスワード (`.env` の変更前の値) を設定し直し、`.env` も戻して③を実行する |

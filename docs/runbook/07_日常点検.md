# 7. 日常の死活監視・点検

定期的に実施する簡易点検のチェックリスト。異常があれば各手順書のトラブルシュートを参照するか、
ベンダーに連絡する。

置き換え: `<TEAM>` `<DIFY_HOST>` `<GATEWAY_HOST>` `<LITELLM_HOST>` `<GATEWAY_DOMAIN>`
`<LITELLM_PORT>` `<REPO_DIR>` `<BACKUP_DIR>`。

## チェックリスト (推奨: 毎営業日 or 週1回)

| # | 確認内容 | 実行VM |
|---|---|---|
| 1 | 各コンテナが running/healthy | 3台すべて |
| 2 | 各チームの外部アクセス | どこからでも可 |
| 3 | LiteLLMのヘルスチェック | LiteLLM VM |
| 4 | ディスク空き容量 | 3台すべて |
| 5 | バックアップが最新化されているか | 3台すべて |
| 6 | TLS証明書の残り日数 | どこからでも可 |

### ① コンテナ状態

```bash
# Dify VM (インスタンスごと)
ssh <DIFY_HOST> "cd <REPO_DIR>/dify/instances/<TEAM> && docker compose ps"

# Gateway VM
ssh <GATEWAY_HOST> "cd <REPO_DIR> && docker compose -p aiop-gateway --env-file .env \
  -f compose.gateway.yaml -f gateway/oauth2-proxies.gateway.yaml ps"

# LiteLLM VM
ssh <LITELLM_HOST> "cd <REPO_DIR> && docker compose -p aiop-litellm --env-file .env \
  -f compose.litellm.yaml ps"
```

全て `running` または `healthy` であればOK。`Exit`/`Restarting`があれば異常。

### ② 外部アクセス確認

```bash
curl -I https://<TEAM>.<GATEWAY_DOMAIN>/
# → 200 か 302 が返ればOK (チームの数だけ繰り返す)
```

### ③ LiteLLMヘルスチェック

```bash
curl http://<LITELLM_HOST>:<LITELLM_PORT>/health/liveliness
# → "I'm alive!" 等の正常応答が返ればOK
```

### ④ ディスク容量

```bash
df -h /
du -sh <BACKUP_DIR>
```

各VMの空き容量が逼迫していないか(目安: 空き20%以上)確認する。逼迫していたら
「バックアップとリストア」の手順書末尾の「古いバックアップの削除」を実施。

### ⑤ バックアップの鮮度

```bash
ls -lt <BACKUP_DIR> | head -5
```

想定どおりの頻度(日次/週次)で新しいファイルが増えているか確認。

### ⑥ TLS証明書の残り日数

```bash
echo | openssl s_client -connect <GATEWAY_HOST>:443 -servername <GATEWAY_DOMAIN> 2>/dev/null \
  | openssl x509 -noout -enddate
```

期限が近づいてきたら「TLS証明書の更新」の手順書で早めに更新の手配をする。

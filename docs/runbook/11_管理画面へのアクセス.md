# 11. 管理画面へのアクセス (LiteLLM・Keycloak)

LiteLLM と Keycloak の管理画面をブラウザで開く手順。モデル追加・仮想キー発行
(LiteLLM) やユーザー・グループ管理 (Keycloak) の前に使う。

置き換え: `<GATEWAY_DOMAIN>` `<GATEWAY_HOST>` `<LITELLM_HOST>` `<LITELLM_PORT>` `<REPO_DIR>`。

| 管理画面 | URL | 動いているVM | ログイン情報 (VM上の `<REPO_DIR>/.env`) |
|---|---|---|---|
| LiteLLM | `http://<LITELLM_HOST>:<LITELLM_PORT>/ui` | LiteLLM VM | `LITELLM_UI_USERNAME` / `LITELLM_UI_PASSWORD` |
| Keycloak | `https://<Keycloakのホスト名>/admin/` (下記A-1で確認) | Gateway VM | `KEYCLOAK_ADMIN` / `KEYCLOAK_ADMIN_PASSWORD` |

> パスワードはこの手順書や設定書に書き残さず、使うたびに VM 上の `.env` で確認すること。

---

## A. LiteLLM 管理画面

### ① ログイン情報を確認

```bash
ssh <LITELLM_HOST>
grep -E '^LITELLM_(HOST|PORT|UI_USERNAME|UI_PASSWORD)=' <REPO_DIR>/.env
```

`LITELLM_HOST` / `LITELLM_PORT` は LiteLLM が待ち受けるIPとポート、
`LITELLM_UI_USERNAME` / `LITELLM_UI_PASSWORD` が管理画面のログイン情報。

### ② ブラウザで開く

```
http://<LITELLM_HOST>:<LITELLM_PORT>/ui
```

①のユーザー名・パスワードでログインする。左メニューに **Models** / **Virtual Keys** 等が
表示されればOK。

### 開けない場合

`.env` の `LITELLM_HOST` が `172.17.0.1` や `127.0.0.1` になっていると、LiteLLM は
**VMの外 (LAN) には公開されていない** (同一VM内からしか届かない既定値)。この場合は
作業PCから SSH のポート転送で開く:

```bash
# 作業PCで実行 (画面を使っている間は開いたままにする)
ssh -L 4000:<.envのLITELLM_HOSTの値>:<LITELLM_PORT> <LITELLM_HOST>
```

ブラウザで `http://localhost:4000/ui` を開く。

- それでも開けない場合は、LiteLLM VM 上で `docker ps --filter name=litellm` を実行し、
  コンテナが `Up (healthy)` になっているか確認する (異常時は日常点検の手順書を参照)。

## B. Keycloak 管理画面

### Keycloak はホスト名で振り分けられている (IPアドレスでは開けない)

Gateway VM の front-nginx は、ブラウザが指定した **ホスト名** を見て転送先を決めている。

| ブラウザで開くホスト名 | 転送先 |
|---|---|
| Keycloak のホスト名 (既定 `auth.<GATEWAY_DOMAIN>`) | Keycloak |
| `<TEAM>.<GATEWAY_DOMAIN>` | 各 Dify インスタンス |
| 上記以外 (`https://<GATEWAY_HOST>/` のような IP 直指定を含む) | **応答せず切断** (ブラウザには「接続がリセットされました」「ERR_EMPTY_RESPONSE」等と表示) |

そのため、作業PCから **Keycloak のホスト名で** アクセスする必要がある。

### Keycloak のホスト名はどこで決まるか

Gateway VM の `<REPO_DIR>/.env` の次の2項目で決まる:

| `.env` の項目 | 意味 |
|---|---|
| `GATEWAY_DOMAIN` | 公開ドメイン。値があれば Keycloak のホスト名は **`auth.<GATEWAY_DOMAIN>`** (例 `auth.example.com`) |
| `GATEWAY_AUTH_HOSTNAME` | Keycloak のホスト名を明示指定する場合に使う。**値があればこちらが優先**される。`GATEWAY_DOMAIN` が空 (フラットなホスト名方式) のときは必須 (例 `auth01`) |

つまり:

- `GATEWAY_AUTH_HOSTNAME` に値がある → その値
- 空 → `auth.<GATEWAY_DOMAIN>`

この値は起動時 (`make gateway-up`) に次の2か所へ反映される。**`.env` を書き換えただけでは
変わらない** (変更した場合は Gateway VM の `<REPO_DIR>` で `make gateway-up` を実行して反映する)。

| 反映先 | 役割 |
|---|---|
| `gateway/nginx/templates/10-auth.conf.template` の `server_name` | front-nginx がこのホスト名のアクセスを Keycloak へ転送する |
| `compose.gateway.yaml` の `KC_HOSTNAME` | Keycloak 自身が名乗るURL (ログイン後のリダイレクト先等) |

> Keycloak のホスト名を変更すると、EntraID 側に登録したリダイレクトURI
> (`https://<Keycloakのホスト名>/realms/<realm>/broker/entraid/endpoint`) やTLS証明書の
> 対象名も合わせて変更が必要になる。

### ① ホスト名とログイン情報を確認

```bash
ssh <GATEWAY_HOST>
grep -E '^(GATEWAY_DOMAIN|GATEWAY_AUTH_HOSTNAME|KEYCLOAK_REALM|KEYCLOAK_ADMIN|KEYCLOAK_ADMIN_PASSWORD)=' <REPO_DIR>/.env
```

上記のルールで Keycloak のホスト名 (以下 `<AUTH_HOST>`) を決める。
`KEYCLOAK_REALM` は運用で使う realm 名 (既定 `aiop`)。

### ② 作業PCから `<AUTH_HOST>` が引けることを確認

```bash
# 作業PCで実行 (Windows の場合は PowerShell で同じコマンド)
nslookup <AUTH_HOST>
```

`<GATEWAY_HOST>` の IP が返ればOK。返らない場合は次のどちらかで対応する:

- **DNSに登録する (推奨)**: 社内DNSに `<AUTH_HOST>` → `<GATEWAY_HOST>` のレコードを追加するよう
  DNS管理者に依頼する。通常は Dify 用のレコードと一緒に登録済み。
- **作業PCの hosts ファイルに追記する (暫定)**: 管理者権限で次の1行を追記する。
  - Windows: `C:\Windows\System32\drivers\etc\hosts`
  - Mac / Linux: `/etc/hosts`

  ```
  <GATEWAY_HOSTのIP>  <AUTH_HOST>
  ```

### ③ ブラウザで開く

```
https://<AUTH_HOST>/admin/
```

①の `KEYCLOAK_ADMIN` / `KEYCLOAK_ADMIN_PASSWORD` でログインする (この管理者は `master`
realm のユーザー)。

ログイン後、画面左上の realm 選択で **`KEYCLOAK_REALM` の値 (既定 `aiop`)** に切り替えてから
Users / Groups を操作する (`master` realm のまま操作しないこと)。

### 開けない場合

| 症状 | 原因と対処 |
|---|---|
| 「サーバーが見つかりません」 | 名前解決できていない → ② をやり直す |
| 接続がリセットされる / 空の応答 | IP や別名でアクセスしている → `<AUTH_HOST>` の綴りが①の値と完全に一致しているか確認 |
| 証明書の警告が出る | TLS証明書に `<AUTH_HOST>` が含まれていない、または期限切れ → TLS証明書の更新の手順書を参照 |
| ログインできない (パスワード誤り) | 管理画面上で管理者パスワードを変更済みの場合、`.env` の値は使えない。変更後のパスワードの保管者に確認する |
| 502 Bad Gateway | Keycloak が停止中 → Gateway VM で `cd <REPO_DIR> && make gateway-ps` を実行し、`keycloak` が `Up (healthy)` か確認する |

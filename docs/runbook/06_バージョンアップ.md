# 6. バージョンアップ (LiteLLM・Gateway)

LiteLLM と Gateway (front-nginx・Keycloak・oauth2-proxy) のイメージ更新手順。
Difyのバージョンアップは「Difyインスタンスの追加・削除・バージョンアップ」の手順書を参照。

置き換え: `<DIFY_HOST>` `<GATEWAY_HOST>` `<LITELLM_HOST>` `<REPO_DIR>`。

> ⚠️ 事前にバックアップを取ってから実施することを推奨します(「バックアップとリストア」の手順書)。

## ① LiteLLM VM (最も簡単・低リスク)

```bash
ssh <LITELLM_HOST>
cd <REPO_DIR>
git pull                       # ベンダーがバージョン指定を更新している場合のみ必要
make pull
docker compose -p aiop-litellm --env-file .env -f compose.litellm.yaml up -d
docker compose -p aiop-litellm --env-file .env -f compose.litellm.yaml ps
```

## ② Gateway VM (front-nginx / Keycloak / oauth2-proxy)

イメージのバージョンは `compose.gateway.yaml` に固定されている。**バージョン変更自体は
ベンダーが行いリポジトリを更新する**ので、担当者は最新化のみ実施する:

```bash
ssh <GATEWAY_HOST>
cd <REPO_DIR>
git pull
docker compose -p aiop-gateway --env-file .env \
  -f compose.gateway.yaml -f gateway/oauth2-proxies.gateway.yaml pull
make gateway-up
docker compose -p aiop-gateway --env-file .env \
  -f compose.gateway.yaml -f gateway/oauth2-proxies.gateway.yaml ps
```

> 各チームのoauth2-proxyのバージョンは、そのチームを追加した時点の `gateway-add.sh` の
> 内容で固定される。既存チーム分を一括更新する仕組みは無いため、oauth2-proxyのバージョンを
> 上げたい場合はベンダーに相談すること。

## 確認

①②内の `docker compose ... ps` で全サービスが running/healthy であることを確認する。

## トラブルシュート

正常に起動しない場合は該当VMで `docker compose ... logs <サービス名>` を確認し、
改善しなければ「バックアップとリストア」の手順で更新前の状態に戻し、ベンダーに連絡する。
